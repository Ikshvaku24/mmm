The model, per account and week

Everything is on the scaled axes. A signed coefficient is built as ±exp(μ + τ·z), so its sign can never flip. Each account gets its own coefficient, shrunk toward a shared mean.

Meridian writes the same model as tau_g + mu_t + Σ beta_gm·AdstockHill(media) + Σ gamma·controls + Σ gamma·non_media (posterior_sampler.py::_joint_dist_base_logic). Ours differs in three deliberate ways:

  • Fourier terms and a trend instead of time knots.
  • Account intercepts are pooled.
  • Price and distribution are reported inside the baseline.

How min and max are set

Every learned transform parameter lives inside a range. You write the range in business units, and the sampler never leaves it. A pin (fix_*) sets min equal to max, and the parameter stops being sampled.

Meridian's default window of 8 supports decay only up to 0.717. Beyond that, a larger decay no longer lengthens the carryover: the window cuts it off and flattens what is left. Our starting windows: TV and Competitor TV 13, digital and OOH 8, BTL 4.

Flags written after the fit

  • at_lower_bound at_upper_bound The bound, not the data, set the value.
  • ec_vs_p95_active Above about 1, the data never reaches half-saturation, and EC50 trades off with β.
  • max_post_corr_with_beta Decay and effect size are trading off. Consider pinning decay.

Priors: ROI by default

Spend exists for paid media, so the prior sits on the number a client or an experiment can actually supply: return per unit of spend.

Why ROI is turned into β on every draw

The sum of Hill(Adstock(x)) changes whenever decay or EC50 change, so no single coefficient prior can stand for an ROI. Each draw works out which β makes incremental sales equal ROI × spend. Meridian does the same in equations.py::calculate_beta_x.

incremental = ROI × Σ spend
R[g]        = dv_scale[g] · Σ_t Hill(Adstock(x̃))[g,t] · revenue_per_unit
μ           = log(incremental) − log( Σ_g exp(τ·z[g]) · R[g] )
β[g]        = exp( μ + τ·z[g] )

Before the first ROI run

  • KPI in money, or ROI in units. A volume KPI needs revenue_per_unit, either a number or a price column. Without it the run stops rather than using a default that means nothing.
  • National spend is allocated, not repeated. The same national budget copied into five accounts makes every ROI five times too low. The spend gate treats this as an ERROR.
  • A sanity band. Posterior ROI outside 0.5–20 is flagged, following Meridian's ImplausibleROIConfig.

ROI prior ladder, weakest to strongest

  1. Nothing known: Meridian's default
  2. A target marketing share: one common ROI, ±50%
  3. A vendor or category ROI: ±30%
  4. Your own experiment: ±10–20%
  5. An imposed benchmark: ±2%, labelled as an assumption

Adapt, don't copy

Codebase 1 assumes every column the sampler sees is fixed before sampling. Learned transforms break that in seven places.

  • Contribution math. Σx becomes Σ Hill(Adstock(x)), which changes on every draw. Print it at the posterior median, beside the per-draw totals.
  • Benchmark correction. It moves onto ROI or contribution share, because there is no longer one coefficient to correct.
  • Collinearity. Before the fit, check raw scaled media; after the fit, check at the posterior-median transform. Label both.
  • Posterior correlation. Add decay, EC50 and peak lag against β. A longer carryover with a smaller coefficient draws almost the same line.
  • Contraction. Add the transform parameters and log-ROI.
  • Media reference. Media is always measured against zero activity.
  • The exception. Carryover-only features keep codebase 1's prior arithmetic, because normalised adstock preserves volume. Only saturation breaks it.

What Phase 2 does not fix

  • The holdout. Codebase 1's test r2_within_region is about −0.66. That comes from the baseline specification (trend and too-smooth seasonality in Q4), not from the transforms.
  • Missing data. The 27-feature retailer datacube has no Category or Competition columns, and no code creates them.
  • Coupon columns. Every value is about 1e-15. That is a broken extract, and the fix belongs with the datacube owner.
  • Spend allocation. The gate detects repeated national spend. The allocation rule is a finance decision.
  • Sampling cost. Learned transforms make the posterior harder to explore. Start at target_accept 0.95.
  • Exogeneity. Spend that follows expected sales cannot be detected from residuals. Experiments, and ROI priors built on them, are the answer.
